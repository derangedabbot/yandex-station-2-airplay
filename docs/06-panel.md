# 06. Веб-панель

Маленькая страница, чтобы не лезть в SSH из-за каждой мелочи: статус, кнопки, хвосты логов.

```
http://<STATION_IP>:8081
```

## Как устроено

В busybox на этой прошивке **нет** `httpd`, поэтому сервер — `socat` из нашего musl-набора:
он слушает порт и на каждое соединение запускает shell-обработчик.

```
сосат :8081  →  panel-handler.sh
                  /                → HTML со статусом
                  /api/status      → JSON
                  /action?do=…&t=… → действия (нужен токен)
                  /log?name=…      → хвост лога
```

Пакетов не добавляется, всё на тех же бинарниках, что уже стоят для AirPlay.

## Что показывает

приёмник, avahi, демон Алисы, порт 5000, играет ли AirPlay сейчас, кто занял звуковое
устройство, сеть (IP, SSID, диапазон из `wpa_cli status`), версия прошивки.

Отдельные блоки под железо и метрики хоста:

* **нагрузка** — загрузка процессора в процентах (разница двух срезов `/proc/stat`),
  `load average` за 1/5/15 минут, число процессов, оперативная память (занято/всего и процент),
  температура (`/sys/class/thermal`), аптайм;
* **железо и диски** — модель из `/proc/device-tree/model`, число ядер, версия ядра,
  занятость разделов: `rootfs` (`/`), `/data` (это `/bkupgrade`), `/tee`.

Важно: на Станции 2 память **NAND с UBI**, а не eMMC — разделов `/cache` и `/system` отдельными
маунтами нет, поэтому показываются реально существующие.

На широком экране первые три блока (состояние, нагрузка, железо) стоят в три колонки,
на телефоне — друг под другом (`@media (min-width:900px)`).

**Статус живой:** страница опрашивает `/api/status` раз в 5 секунд и перерисовывает значения —
не нужно перезагружать, чтобы увидеть, что что-то упало или поднялось. Пока AirPlay играет,
демон Алисы показывается как «Уступлен AirPlay», а не как ошибка.

## Что умеет

| Элемент | Действие |
|---|---|
| Перезапустить AirPlay | убивает приёмник и поднимает заново (лечит «пропал из списка») |
| Выключить AirPlay | останавливает приёмник, звук возвращается Алисе |
| Перезапустить avahi | вторая по частоте причина «пропал» — mDNS подвис; сторож поднимает avahi сам |
| Поднять Алису | перезапускает `maind --mediad` с нужным окружением |
| Перезагрузить | `sync` + `reboot` |
| Логи | хвост по 40 строк: приёмник, распорядитель, avahi, загрузка, обновления, панель |

Регулировки громкости в панели нет: у этого кодека (`SY6045S`) громкость живёт в «сырых»
контролах (`amixer cset numid=N`), софт-регулировка через ALSA даёт рваную шкалу, и на слух
проще пользоваться штатными кнопками колонки. При необходимости заводские значения
восстанавливаются так: `amixer cset numid=1 214; amixer cset numid=2 159; amixer cset numid=3 159`.

## Доступ

* Слушается только домашняя подсеть: `socat …,range=<LAN>/24`. Извне недоступна.
* Действия требуют токен из `/data/local/etc/panel.token` (генерируется при первом запуске,
  `chmod 600`). Страница запоминает его в браузере.
* Статус и логи открыты без токена — но только в своей сети.

Если нужен доступ извне — не открывайте порт в интернет, а поставьте Tailscale
(пакет есть в Alpine, `/dev/net/tun` на колонке присутствует).

## Файлы

* [`scripts/device/panel-server.sh`](../scripts/device/panel-server.sh) — socat + токен + авторестарт
* [`scripts/device/panel-handler.sh`](../scripts/device/panel-handler.sh) — обработчик и HTML

## Установка

```sh
scp panel-server.sh panel-handler.sh root@<STATION_IP>:/data/local/bin/   # или через ssh
chmod 755 /data/local/bin/panel-*.sh
ln -sf /data/local/bin/socat1 /data/local/bin/socat      # обёртка из набора
start-stop-daemon -S -b -m -p /run/panel.pid -x /bin/sh -- /data/local/bin/panel-server.sh
```

Автозапуск — строка в `/etc/init.d/S97station-root` (см. `02-persistence.md`).

## Грабли

* `socat` в наборе называется `socat1` (Alpine 1.8) — нужен симлинк `socat`.
* **У `socat` по умолчанию 0.5 с на обмен** — `/api/status` собирается дольше, соединение
  рвётся, панель получает пустой ответ, и кнопки выглядят мёртвыми. Нужен `socat -t 10 TCP-LISTEN:…`.
* Владельца звука не искать перебором всех `/proc` (это 4 с на запрос): брать `owner_pid` из
  `/proc/asound/card0/pcm0p/sub0/status`, перебор — только если pid мёртв. Стало ~0.8 с
  холодный статус и ~0.1 с из кэша.
* Никогда не проверяйте наличие процессов грепом по слову, которое есть в вашей же команде:
  `ssh 'ps w | grep updatesd'` покажет вашу же строку и соврёт. Грепать с `[u]pdatesd`
  и в отдельной команде.

## Карточка «AirPlay»

Отдельная карточка управляет тем, что играет с Mac или iPhone: **Назад**, **Пауза / играть**,
**Дальше**. Это не наш плеер — команда уходит источнику plist-ом `sendMediaRemoteCommand`
через канал событий сессии (подробности в [`03-airplay.md`](03-airplay.md)).

В `/api/status` появилось поле `airplay` (1 — сессия активна, 0 — нет): оно считается по
установленному соединению на порт 7000, поэтому карточка честно показывает состояние, даже когда
`shairport-sync` просто ждёт подключения.

Действия панели: `airplay-prev`, `airplay-toggle`, `airplay-next` — тонкие обёртки над
`/data/local/bin/airplay-ctl.sh`.

## Карточка «Сказать Алисе»

Поле и четыре быстрые кнопки: «Моя волна», «Громкость 3», «Погода», «Стоп». Текст уходит
в отладочный CLI движка (`maind --cli`: `q` → текст → `x`) — это ровно то же, что произнести
фразу голосом, включая ответ вслух.

Скрипт: `scripts/device/alice-say.sh` — один запуск за раз (pid-файл), ограничение по времени,
запись отправленного в `/data/local/tmp/alice-say.log`. Команда уходит **один раз**: никаких
повторов и «дожатий», поэтому со звуком она не воюет — просто просит колонку что-то сделать.

Текст передаётся в base64 (`t64=`), потому что обработчик панели не декодирует URL —
по той же причине поиск ходит через `q64=`.
