# 11. Свой звук её собственным плеером (`audio_play`)

Короткий вывод, который стоил нам нескольких дней: **свой файл на Станции можно играть её
родным плеером**, не воюя за звуковое устройство и не выключая Алису. Ниже — как это устроено
и на чём мы спотыкались.

## Схема

1. Демон на колонке скачивает трек (у нас — из «Звука») в свою папку.
2. Поднимает HTTP-раздатчик на `8765` и отдаёт ссылку `http://127.0.0.1:8765/<файл>?t=<метка>`.
3. Ссылка уходит штатному плееру командой Glagol:

```
externalCommandBypass → protobuf {1: "audio_play", 2: JSON{
    "stream": {"url": "http://127.0.0.1:8765/…", "format": "MP3", "type": "Track", "offset_ms": 0},
    "set_pause": false
}}
```

4. Файл забирает `maind --mediad`. Играет он — значит Алиса остаётся на связи, громкость,
   пауза и мультирум работают как обычно.

`radio_play` для этого **не годится**: на `.50` он включает «радио Яндекса» и присланную ссылку
игнорирует (в её логе появляется сущность `FmRadio`). Ответ `SUCCESS` означает лишь, что
команда принята, а не что заиграла наша ссылка — проверять только по её логу
`/data/quasar/daemons_logs/mediad.log*`: там должно быть
`AudioClient created … uri=http://127.0.0.1:8765/…`.

## Что обязательно должно работать в раздатчике

**`Range`.** На `Range: bytes=<start>-` нужно отвечать `206` с честными `Content-Range` и
`Content-Length`, а в `HEAD`/`200` — `Accept-Ranges: bytes`. Без этого станция не может начать
с середины и молча откатывается на нулевую секунду: пауза позицию держит, а «продолжить»
играет сначала.

Файл должен отдаваться с настоящей длиной (`Content-Length`): chunked и «бесконечные» потоки
она рвёт.

## Пауза, продолжение, конец трека

- **Пауза — только вместе с потоком.** Отдельная команда `{"command":"pause"}` её плеером
  игнорируется: звук продолжается, хотя наш счётчик встаёт. Работает та же `audio_play`, но с
  `"set_pause": true` в одной посылке. Проверять надо её поле `playing`, а не свой счётчик.
- **Продолжение — снова `audio_play`** с `offset_ms`, равным позиции паузы. Команда `play`
  возобновляет **её прошлую сущность** (например, «32 радио»), а не наш файл.
- **Конец трека** определять по её позиции/длительности, а не по тому, что «байты перестали
  отдаваться»: файл докачивается за секунды, и иначе очередь перескакивает через 10 секунд
  после старта.
- Позицию на паузе надо **замораживать**: если считать её по времени с начала воспроизведения,
  продолжение прыгает вперёд на длительность паузы.

## Голос и AirPlay

Локальный слушатель голоса ставит свои команды с задержкой 1.5 с: её облако отвечает позже и
на «продолжи»/«дальше» запускает свой поток. Подробности — [`09-voice.md`](09-voice.md).

При активном AirPlay (`shairport-sync`) звук держит приёмник, а `mediad` приходится гасить —
иначе они дерутся за одно устройство. Арбитраж описан в [`03-airplay.md`](03-airplay.md).

Плеер уступает сам, причём порт приёмника берётся не «из головы», а из двух вариантов:
до shairport-sync 5.6 AirPlay 2 слушал фиксированный `7000`, в 5.6+ — `port` из конфига
(у нас `5000`). Проверяем оба, иначе после обновления приёмника арбитраж молча отключается:
плеер играет, приёмник получает `EBUSY`, AirPlay звучит в тишину. если есть установленное соединение на `7000`, он ставит трек на паузу
(`set_pause`, позиция сохраняется), а после конца сессии продолжает с той же секунды. Пауза
помечается флагом, поэтому паузу, поставленную человеком, автоматика не снимает.
